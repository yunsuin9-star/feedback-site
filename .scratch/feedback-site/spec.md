# 피드백 사이트 Spec

## 1. 개요

- 기능 이름(feature-slug): `feedback-site`
- 목적: 수업 과제의 객관식·서답형 답변, 교사 피드백, 학생별 오개념, 학급 전체의 익명 오개념 변화를 한 곳에서 확인한다.
- 사용자: 학생, 선생님
- 화면 구현: 모든 화면을 `index.html` 하나에 넣고, 페이지 이동 대신 화면 상태를 바꾸어 표시한다.
- 저장: 서버나 데이터베이스 없이 브라우저 `localStorage`에 저장한다.
- 확인 방법: 자동화된 테스트 도구를 사용하지 않고 브라우저에서 직접 화면과 동작을 확인한다.

## 2. 범위와 제외 범위

### 포함

1. 선생님이 수업 코드를 발급한다.
2. 학생이 테스트용 전화번호 인증과 수업 코드 입력으로 수업에 참여한다.
3. 선생님이 객관식 2개, 서답형 1개, 공개일·마감일, 핵심 개념, 예상 오개념을 입력한다.
4. 학생이 과제를 확인하고 답변을 제출하거나 마감 전에 최대 2회 수정한다.
5. 선생님이 서답형 답변에 점수와 피드백을 남긴다.
6. 학생이 자신의 답변 결과와 피드백, 오개념 결과를 확인한다.
7. 선생님이 오개념 후보를 확인하고 수정한다.
8. 선생님이 최근 6주 결과의 익명 학급 오개념 위계와 누적 변화를 확인한다.

### 만들지 않음

- 실제 문자 발송 기능
- 학생 간 답변·피드백 공유
- 다른 학생의 이름 또는 개인 분석 공개
- 마감 후 답변 수정
- 마감 전 2회를 초과한 답변 수정
- 객관식 2개와 서답형 1개 이외의 문제 유형
- 학생에게 학급 전체의 개인별 오개념 공개
- 실시간 채팅 또는 별도 소셜 기능
- 서버, 데이터베이스, 로그인 계정, 외부 인증 연동

기존에 사용하던 도구나 절차는 정하지 않고 이 기능의 범위에서 제외한다. (AI 제안)

## 3. 화면 구조

모든 화면은 `index.html` 안에서 현재 역할과 화면 상태에 따라 하나씩 표시한다.

### 3.1 시작 화면

- `선생님`과 `학생` 역할을 선택한다.
- 선생님은 수업 생성 화면으로 이동한다.
- 학생은 전화번호 인증 및 수업 참여 화면으로 이동한다.
- 역할 선택은 현재 브라우저에서 사용할 화면을 정하기 위한 것이며 별도 계정을 생성하지 않는다. (AI 제안)

### 3.2 선생님 수업 생성 화면

- 선생님 화면은 관리자 화면이므로 관리자 비밀번호를 입력해야 열 수 있다.
- 실습용 관리자 비밀번호는 `teacher-demo`로 한다.
- 관리자 비밀번호를 입력하기 전에는 학생 글, 학생별 답변·점수·피드백·오개념, 학급 분석 등 선생님만 보는 내용이 화면에 보이지 않는다.
- 수업 코드를 발급한다.
- 발급한 수업 코드와 연결된 과제 입력 폼을 제공한다.
- 과제 입력 항목:
  - 객관식 문제 1: 문제 내용, 선택지, 정답
  - 객관식 문제 2: 문제 내용, 선택지, 정답
  - 서답형 문제 1: 문제 내용
  - 공개일
  - 마감일
  - 핵심 개념
  - 예상 오개념 목록
- 저장 후 선생님 화면에서 해당 수업의 과제 관리 화면으로 이동한다.
- 수업 코드는 숫자 6자리로 자동 발급한다. (AI 제안)

### 3.3 학생 수업 참여 화면

- 전화번호를 입력한다.
- 테스트용 인증번호를 입력한다.
- 인증이 완료되면 수업 코드를 입력한다.
- 코드가 존재하면 해당 수업의 과제 화면으로 이동한다.
- 실제 문자를 보내지 않으며, 테스트 인증번호는 `000000`으로 고정한다. (AI 제안)

### 3.4 학생 과제 화면

- 공개일 전에는 과제 내용을 보여주지 않고 공개 예정 상태를 표시한다.
- 공개일 이후 마감 전에는 객관식 2개와 서답형 1개를 입력할 수 있다.
- 제출 전에는 답변을 수정할 수 있다.
- 제출 후에는 제출한 답변과 제출 시각을 보여준다.
- 제출 후 마감 전에는 답변 수정 횟수와 남은 횟수를 보여준다.
- 최초 제출 뒤 최대 2회까지 수정 제출할 수 있다. (AI 제안)
- 마감 시각이 되면 제출과 수정을 막는다.

### 3.5 선생님 답변·피드백 화면

- 수업에 참여한 학생별 제출 답변을 확인한다.
- 객관식 답변에는 정답 여부를 표시한다.
- 서답형 답변에는 점수와 피드백을 입력하고 저장한다.
- 저장한 점수와 피드백은 해당 학생의 결과 화면에 표시한다.
- 객관식 정답 여부는 선생님이 별도로 수정하지 않고 입력된 정답과 학생 답변을 비교해 계산한다.

### 3.6 선생님 오개념 확인 화면

- 학생별 객관식 오답과 서답형 답변을 확인한다.
- 시스템이 제시한 오개념 후보를 학생별로 표시한다.
- 선생님은 후보를 확인하거나, 후보를 수정·삭제하거나, 예상 오개념 목록에서 다른 항목을 선택할 수 있다.
- 선생님이 저장한 최종 오개념 결과만 학생에게 공개한다.
- 첫 버전의 후보는 과제에 입력된 예상 오개념 목록을 후보로 제시하고, 객관식 오답과 서답형 답변을 판단 근거로 함께 보여준다. (AI 제안)

### 3.7 학생 결과 화면

- 학생 본인의 객관식 답변과 정답 여부를 보여준다.
- 학생 본인의 서답형 답변, 점수, 선생님 피드백을 보여준다.
- 선생님이 확정한 본인의 오개념 결과를 보여준다.
- 다른 학생의 답변, 이름, 점수, 피드백, 오개념은 보여주지 않는다.

### 3.8 선생님 학급 분석 화면

- 최근 6주 동안의 수업 결과를 주 단위로 집계한다.
- 학생 이름 없이 핵심 개념과 오개념의 위계를 보여준다.
- 주별 오개념 수와 누적 변화를 보여준다.
- 개인별 결과나 개인을 식별할 수 있는 정보는 포함하지 않는다.
- 최근 6주는 현재 날짜가 포함된 주를 기준으로 현재 주와 직전 5개 주를 표시한다. (AI 제안)
- 위계는 `핵심 개념 > 오개념`의 2단계로 표시한다. (AI 제안)

## 4. 주요 동작 규칙

### 과제 공개와 마감

- 공개일 이전: 학생은 과제 문제와 답변 입력을 사용할 수 없다.
- 공개일 이후, 마감일 이전: 학생은 답변을 제출하거나 남은 수정 횟수 안에서 수정할 수 있다.
- 마감일 이후: 학생은 답변을 제출하거나 수정할 수 없다.
- 공개일과 마감일은 브라우저의 현재 시간을 기준으로 비교한다. 마감 시각 이상이면 마감으로 처리한다. (AI 제안)
- 마감일은 공개일보다 늦어야 저장할 수 있다.

### 답변과 수정

- 객관식은 문제별로 하나의 선택지를 저장한다.
- 서답형은 하나의 텍스트 답변을 저장한다.
- 최초 제출을 수정 횟수에 포함하지 않는다.
- 수정 제출할 때마다 수정 횟수를 1 증가시킨다.
- 수정 횟수가 2가 되거나 마감되면 수정 버튼을 비활성화한다.

### 피드백과 오개념

- 객관식 정답 여부는 교사가 입력한 정답과 학생의 선택이 같은지로 계산한다.
- 서답형 점수와 피드백은 선생님이 저장하기 전에는 학생에게 보이지 않는다.
- 오개념은 선생님이 확인·수정 후 저장해야 학생에게 보인다.
- 학급 분석에는 선생님이 확정한 오개념만 집계한다.

## 5. localStorage 데이터

브라우저 `localStorage`에 다음 데이터를 JSON으로 저장한다. 키 이름은 구현 시 아래 이름을 사용한다.

- `feedbackSite.courses`: 수업 목록
  - `id`, `code`, `createdAt`
  - 과제 정보: 문제 2개, 서답형 문제, 공개일, 마감일, 핵심 개념, 예상 오개념 목록
- `feedbackSite.students`: 전화번호 인증을 마친 학생 식별 정보
  - `id`, `phone`, `courseId`
- `feedbackSite.submissions`: 학생별 제출 정보
  - `courseId`, `studentId`, 객관식 답변 2개, 서답형 답변, `submittedAt`, `revisionCount`
- `feedbackSite.feedback`: 서답형 점수와 피드백
  - `courseId`, `studentId`, `score`, `comment`, `updatedAt`
- `feedbackSite.misconceptions`: 선생님이 확정한 학생별 오개념
  - `courseId`, `studentId`, `items`, `updatedAt`

각 브라우저의 `localStorage`를 단일 저장소로 사용하므로, 별도 서버 없이 같은 브라우저에서 선생님과 학생 화면을 확인하는 데모로 동작한다. (AI 제안)

## 6. 입력 검증과 오류 표시

- 수업 코드가 없으면 학생에게 참여할 수 없다는 안내를 표시한다.
- 인증번호가 맞지 않으면 학생 화면에 인증 실패를 표시한다.
- 선생님 관리자 비밀번호가 맞지 않으면 선생님 화면을 열지 않고 인증 실패를 표시한다.
- 관리자 비밀번호를 입력하기 전에는 학생 글과 선생님만 보는 내용이 화면에 보이지 않는다.
- 문제, 선택지, 정답, 공개일, 마감일, 핵심 개념은 비어 있을 수 없다.
- 객관식 정답은 해당 문제의 선택지 중 하나여야 한다.
- 서답형 답변은 제출할 때 입력되어 있어야 한다.
- 마감일이 공개일보다 빠르거나 같으면 저장하지 않고 오류를 표시한다.
- 저장이 성공하면 현재 화면에 성공 상태를 표시한다.

## 7. 수동 확인 기준

자동화된 테스트 도구는 사용하지 않는다. 브라우저에서 다음 흐름을 직접 확인한다.

1. 선생님 역할로 수업 코드를 발급하고 과제를 저장한다.
2. 학생 역할로 테스트 인증번호와 수업 코드를 입력해 참여한다.
3. 공개된 과제에서 객관식 2개와 서답형 1개를 제출한다.
4. 마감 전 수정 제출을 2회 수행하고, 세 번째 수정이 막히는지 확인한다.
5. 선생님 화면에서 객관식 정답 여부와 서답형 답변을 확인하고 점수·피드백을 저장한다.
6. 오개념 후보를 확인·수정하고 저장한다.
7. 학생 화면에서 본인의 정답 여부, 점수, 피드백, 오개념만 보이는지 확인한다.
8. 선생님 화면에서 학생 이름 없이 6주 오개념 위계와 누적 변화가 보이는지 확인한다.
9. 마감 후 제출·수정이 막히는지 확인한다.

## 8. 완료 조건

- 요구된 모든 화면이 `index.html` 하나에서 전환된다.
- 새로고침 후에도 `localStorage`에 저장한 수업, 답변, 피드백, 오개념이 유지된다.
- PRD에서 만들지 않기로 한 기능이 화면이나 동작에 포함되지 않는다.
- 위 수동 확인 흐름을 브라우저에서 직접 완료할 수 있다.
